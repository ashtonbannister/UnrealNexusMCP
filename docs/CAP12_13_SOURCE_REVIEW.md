## CAP-12: source-backed Control Rig creation

| Candidate | Source-observed contract | Boundary before admission |

| UE-MCP `animation.create_control_rig` | [Pinned factory handler](https://github.com/db-lyon/ue-mcp/blob/62bb9a8f4a41b8ce5ff9a0fbbd5fbe0f49a39c7d/plugin/ue_mcp_bridge/Source/UE_MCP_Bridge/Private/Handlers/Animation/AnimationHandlers_ControlRig.cpp#L258-L355) requires exactly one mesh or skeleton source, accepts only skip/error conflict policy, invokes the source-backed factory, attempts relocation, and reports `saved` plus `saveError`. | `success` does not by itself mean persisted: explicitly require `saved:true` for a persisted contract. A moved asset that cannot be reloaded or an unsuccessful save may leave side effects, so preserve receipts and require external reconciliation. Review exact public schema, factory guard and destination collision against actual engine build. |
| EngineWire Control Rig | [Pinned creation path](https://github.com/ChiR24/Unreal_mcp/blob/5a17d6d343ef9b40a509068cff73f1bfb4509815/plugins/EngineWire/Source/EngineWire/Private/Domains/AnimationAuthoring/McpAnimControlRig.cpp#L15-L169) allows blank creation, a modular option and optional saving; mesh takes precedence if both sources are supplied. Its source-backed path attempts relocation but does not reject a failed rename there. Its older-engine fallback constructs a Blueprint and can set a preview mesh rather than establishing an equivalent imported rig hierarchy. | These blank, modular, unsaved and compatibility-mode cases are distinct proposed contracts, not substitutes for exactly-one-source persisted creation. Verify collision handling, actual output path, hierarchy and save independently; do not infer a complete rig from a successful asset receipt. |

A source-preferred candidate is not a callable route. Before any canonical child is selected, specify a stable source and destination, class, engine/plugin/factory availability, conflict result, relocation and save behavior, dirty and on-disk outcomes, and the treatment of partial failure. A returned inverse/delete descriptor is not evidence that a rollback ran or succeeded. The existing [Control Rig audit](audit/specialized.md#control-rig) and [component notices](../THIRD_PARTY_NOTICES.md) remain applicable; inspect the precise provider and dependency license before any code reuse.

**Fixture and native gates:** reject absent or conflicting source selectors and invalid or already-existing destinations before mutation; check no overwrite on both conflict policies. Exercise missing mesh/skeleton, absent plugin/factory, relocation failure, reload failure, save failure and lost post-dispatch receipt while preserving observable partial artifacts. Require one dispatch and no automatic retry. In a disposable selected engine/project, record source skeleton and bone hierarchy, preview mesh, solve directions, actual created asset path, package dirty state and save/reload. Demonstrate an unchanged animation round trip and separately qualify modular/blank/older-engine variants if chosen. Source/fixture checks alone cannot establish hierarchy, real animation, loaded code or persistence.

## CAP-13: distinct Sequencer contracts

| Candidate | Source-observed contract | Boundary before admission |
| --- | --- | --- |
| EngineWire `manage_sequence.add_keyframe` | [Pinned keyframe implementation](https://github.com/ChiR24/Unreal_mcp/blob/5a17d6d343ef9b40a509068cff73f1bfb4509815/plugins/EngineWire/Source/EngineWire/Private/Domains/Sequence/McpSeqKeyframes.cpp#L112-L193) resolves a sequence and binding, converts display-frame input to ticks, extends playback range when a key lies outside it, and can create the relevant track/section. A batch failure after earlier writes explicitly reports prior keys written. | Keep track/section creation, range changes and batch partial effects visible. Do not infer atomicity, disk persistence, exact object targeting from a label, or playback success from a request receipt. Verify first-bound-object behavior and defaults for unspecified transform axes. |
| UE-MCP `editor.set_sequence_channel_keys` | [Pinned channel implementation](https://github.com/db-lyon/ue-mcp/blob/62bb9a8f4a41b8ce5ff9a0fbbd5fbe0f49a39c7d/plugin/ue_mcp_bridge/Source/UE_MCP_Bridge/Private/Handlers/Sequencer/SequencerHandlers_Channels.cpp#L404-L549) validates key inputs before writes, resolves an existing channel (with a parameter-section creation path), writes keys/defaults, marks the package dirty, and reports key readback and mismatches. Its inverse explicitly says custom tangents are not restored and created parameters remain. | A dirty package is not a persisted asset. Validate selectors, key count, verified count and mismatch details; same-time duplicates and mixed default/clear behavior need separate fixtures. A parameter creation followed by a later failure may have side effects. The lossy inverse is not a transactional rollback or a proof of undo. |
| Hayba `seq_transform_keyframe` | [Pinned Python-backed convenience operation](https://github.com/zajalist/hayba/blob/b69ed11011f89aed3c444a50bd2331b99551c777/mcp-tools/hayba-mcp/src/tools/sequencer/sequencer-py-tools.ts#L409-L491) chooses the first matching transform track/section or creates one, identifies channels by display-name patterns, catches individual add-key exceptions, attempts save and emits `keys_added`. | It can report an otherwise successful envelope with zero keys added or partial channels, and the shown save call does not establish saved state. It is not an equivalent checked-write default. No arbitrary Python operation is admitted by this comparison. |

A prospective canonical child must distinguish exact existing-channel editing from track/section creation, bind a specific sequence, binding, track and section, and define time units, display rate, tick conversion and rounding. Capture keys, interpolation, defaults and relevant ranges before and after; do not conflate raw key creation with evaluated playback. Exclude ambiguous names and stale identities unless a native boundary can prove the intended target. A partial multi-key batch must report completed and failed effects without claiming atomicity. Decide explicitly whether saving is separate or part of the contract, and verify reload for persistence claims.

**Fixture and native gates:** use exact selectors; test fractional display rates and frame-to-tick conversion, same-tick replacement and duplicate inputs, out-of-range keys, missing or ambiguous tracks/sections, wrong binding/world, unsupported channel types, bad values after an earlier valid batch item, and no-key/partial success. Inspect default values and location/rotation/scale when axes are omitted, active and playback ranges, value readback, custom tangents and the lossiness of any proposed inverse. Inject save and post-dispatch failures without replay, preserve per-item results, and test reopen/readback of the actual selected sequence. Native qualification additionally requires identified provider binaries, editor epoch, engine/project revision and observed playback; fixture/source evidence cannot establish those results.
