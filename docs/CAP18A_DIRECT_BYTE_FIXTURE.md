# CAP-18A direct-byte protocol: fixture-stage exploration

Status: **historical candidate fixture**, superseded for routing by the [direct PIE implementation and evidence](qualification/UE_DIRECT_PIE_CAPTURE_WIP_20261112.md). This is not a native patch, a selected executable route, a provider promotion, or live qualification. The former path-writing `screenshot.pie` route was held at the time of this fixture. The existing [transport evidence](CAP18A_TRANSPORT_DECISION_EVIDENCE.md) and [source transport review](CAP18A_SOURCE_TRANSPORT.md) describe why neither a path-based preflight nor the current response framing proves a safe boundary.

## Candidate fixture and trust boundaries

`parseCap18DirectFrame` in `src/cap18-direct-frame.mjs` explores an intentionally narrow, flat JSON response with a version, request nonce, host editor epoch and project identity, exact world and PIE instance, dimensions, canonical base64 PNG and SHA-256. It checks a bounded, already-received raw buffer, fatal UTF-8, duplicate or unexpected keys, exact expected identities, canonical base64, hash, and a restricted metadata-free PNG policy. The parsed candidate fields and an MCP image-shaped block are returned; original raw JSON bytes and formatting are not retained by this helper. No gateway dispatch uses this function, and the names are a proposed fixture schema, not fields observed from the pinned native bridge.

The caller must supply positive limits: this fixture rejects limits above 16 MiB raw frame, 8 MiB PNG, 4 Mi pixels, and 4096 pixels per dimension. These are **provisional test ceilings**, not measured service budgets, compatibility claims or an authorization to allocate those amounts in a production server. The raw buffer is already allocated before this function begins: a real bridge must enforce a smaller reviewed limit on receive and decompression before constructing the full message or calling JSON.parse. A downstream image block duplicates base64 data alongside the parsed receipt; retaining the original raw receipt would add another full-frame copy. Response-size and concurrent-memory budgets must cover all copies, the whole output and overhead, not just the PNG.

Expected request/project/editor/world values must come from trusted host state, not from the native response or model. Equality against those values only correlates a declared identity; it does not independently attest the editor, establish uniqueness of a PIE world, prove the loaded build, or establish that the returned pixels came from the selected viewport. The fixture has no native marker and does not authenticate a backend. It preserves the declared envelope but currently has no warning or arbitrary-metadata fields: the real fixed protocol must define bounded warnings and preserve the original native receipt and MCP metadata without an arbitrary backend escape. The strict metadata-free PNG subset may reject legitimate Unreal PNGs and is not a full image-decoder safety guarantee.

## Work still required before exposure

1. Agree an immutable source-pinned compatibility delta and a fixed native method with a live marker. Select one exact PIE world and reject duplicates; report actual world and instance. Re-attest the project/editor epoch before dispatch and ensure host-generated request correlation cannot be chosen by the model.
2. Enforce reviewed pixel, encoded-byte, frame and concurrent-memory limits before native capture/encoding and before WebSocket reassembly or decompression. Disable or explicitly bound transport compression as appropriate. Account for UTF-8 JSON/base64 and the complete MCP output. Verify actual runtime dependencies, not only source pins.
3. Define bounded receipt/warning/error fields, cancellation and post-dispatch uncertainty; malformed, stale, crossed or interrupted responses must fence subsequent work. The existing process-local queue does not coordinate direct clients. No retries or provider fallback follow an uncertain capture.
4. Add a fixed adapter and capability probe only after the native contract and loaded marker can be checked. Test limits before allocation, fragmented/compressed frames, malformed and duplicated fields, multiple PIE clients, timeouts and cross-client fencing. Validate PNG handling with a reviewed bounded decoder and preserve all legitimate diagnostics.
5. Build and inspect the actual native/server artifacts, verify exact loaded identities, and execute the LIVE-03 interactive cases with real recognizable pixels, UI and client selection. Source and fixtures do not meet that gate. A change in image/file semantics requires explicit catalog, documentation and rollback evidence.

The tests in `test/cap18-direct-frame.test.mjs` establish only this candidate local parser's stated bounds and correlation behavior. They do not test a WebSocket, native capture, resource exhaustion before receipt, real image decoding, or actual Unreal output. No temporary-file fallback is implied.
