# CAP-03–06: world and asset source review

Status: source and fixture planning only, not an added canonical route, completed contract, safety claim, or native qualification. Review is scoped to the immutable source slices linked below and existing [world/asset audit](audit/world-assets.md) and [decision records](../catalog/decisions.json). CAP-01 remains a prerequisite; the reviewed code does not establish an atomic lock between a separate discovery/preflight and a later native mutation. All proposed contracts below require source-specific schemas, fixed selectors, fixture evidence and actual editor acceptance before promotion. World Partition, unloaded content, editor versus PIE and multiple clients remain explicit boundaries.

## CAP-03: exact world actor authoring

**Transform candidate.** The pinned EngineWire [`HandleControlActorSetTransform`](https://github.com/ChiR24/Unreal_mcp/blob/5a17d6d343ef9b40a509068cff73f1bfb4509815/plugins/EngineWire/Source/EngineWire/Private/Domains/ControlActor/McpActorTransform.cpp#L99-L182) resolves `actorName`, supports absolute location or offset, writes location/rotation/scale and reports observed values with location, quaternion and scale tolerances. It returns `TRANSFORM_MISMATCH` with readback if the engine outcome differs. The pinned [lookup](https://github.com/ChiR24/Unreal_mcp/blob/5a17d6d343ef9b40a509068cff73f1bfb4509815/plugins/EngineWire/Source/EngineWire/Private/Domains/ControlActor/McpActorLookup.cpp#L5-L117) is PIE-first and can resolve a label/name; this does not prove a caller-selected editor world or exact PIE instance. The [UE explicit-world movement](https://github.com/db-lyon/ue-mcp/blob/62bb9a8f4a41b8ce5ff9a0fbbd5fbe0f49a39c7d/plugin/ue_mcp_bridge/Source/UE_MCP_Bridge/Private/Handlers/Level/LevelHandlers.cpp#L2000-L2099) is a distinct candidate, not a drop-in replacement. Do not admit the conditional EngineWire candidate with a name-only preflight: another client or editor event can change target identity between checks. Require same-dispatch explicit world/editor epoch, exact actor identity and native revalidation, and preserve mismatch/partial effects instead of retrying.

**Spawn and typed properties.** No candidate has been selected. The task requires a separate child contract for each class/type and explicit world, collision handling, returned actor identity, dirty package and persistence. A property edit must validate reflected type, mutability and allowed value before dispatch, report per-property effects and read back actual state. Spawn, duplicate and changing an existing actor have distinct collision, attachment and persistence semantics. Candidate implementation and schemas are not fully reviewed in this slice; do not infer a safe route from operation names.

**Fixture and live gates.** Use duplicate labels, editor and two PIE worlds, stale path reuse, a constrained actor and distinct transforms. Verify wrong/stale world refusal before mutation, no automatic retry after interruption, tolerance mismatches and partial writes in receipt. For editor-world edits separately save the intended level, inspect package effects and reload; a PIE mutation is not persisted editor state. Test spawn collision policy, class/type errors and no-op/readback independently. Fixture evidence must include the native revalidation contract; only a real editor can establish actual engine physics and persistence.

## CAP-04: trusted scoped asset import

The pinned UE [`ImportFile`](https://github.com/db-lyon/ue-mcp/blob/62bb9a8f4a41b8ce5ff9a0fbbd5fbe0f49a39c7d/plugin/ue_mcp_bridge/Source/UE_MCP_Bridge/Private/Handlers/Asset/AssetHandlers_Import.cpp#L880-L1025) takes a local filename and destination, supports explicit factory validation and factory-property preparation, and invokes AssetTools. Its `replaceExisting` native default is **true**; the reviewed handler can save each returned asset, emits per-asset save state and reports an error after partial save failure. It checks source existence before importing, not a pinned immutable file handle. Explicit `replaceExisting=false` is necessary for the candidate but is not proof that every factory honors collision policy or that a changing source is safe.

[EngineWire import](https://github.com/ChiR24/Unreal_mcp/blob/5a17d6d343ef9b40a509068cff73f1bfb4509815/plugins/EngineWire/Source/EngineWire/Private/Domains/AssetWorkflow/Operations/McpAssetImportDuplicate.cpp#L20-L345) has source-boundary and Interchange behavior with different persistence semantics. [Hayba's Windows restricted import](https://github.com/zajalist/hayba/blob/b69ed11011f89aed3c444a50bd2331b99551c777/unreal/HaybaMCPToolkit/Source/HaybaMCPToolkit/Private/handlers/HaybaMCPAssetHandler.cpp#L1205-L1565) is a distinct pinned-handle/lease candidate, not an interchangeable generic factory route. Exact scope, plugin support and applicable license still require examination.

A future generic-import contract needs an owner-authorized source root and exact destination, a reviewed factory and expected output class, enforced no-replacement behavior and identity checks through dispatch, bounded output, all produced object rows and per-package save results. A path spelling or a preflight existence check alone is not source ownership or a race-free no-overwrite guarantee. Fixture tests should inject replaced/changed source, unsupported factory, occupied destination, zero produced assets and a second save failure after a first success; retain all receipts and do not retry uncertain mutation. Native acceptance must independently inspect asset registry, actual package bytes and reload. Specialized skeletal and Interchange contracts remain separately reviewed.

## CAP-05: rename, move and duplicate

The pinned EngineWire [ordinary rename](https://github.com/ChiR24/Unreal_mcp/blob/5a17d6d343ef9b40a509068cff73f1bfb4509815/plugins/EngineWire/Source/EngineWire/Private/Domains/AssetWorkflow/Operations/McpAssetAssetMutation.cpp#L18-L127) sanitizes paths, checks source and destination existence and calls its settings-follow rename helper; it adds verification if the renamed asset can be loaded. The same handler recognizes a directory and dispatches an entire folder move. Settings-follow effects can extend beyond an asset rename, and verification is conditional on load: neither behavior alone proves exact scoped persistence. Keep the candidate conditional; bind a child contract to an exact source object and destination package, reject folder inputs and disallowed asset types, and review helper side effects and precondition timing before a route is selected.

World Partition migration with external packages and redirector-fixing folder moves are distinct contracts. Duplication also has its own destination collision, resulting object identity and save semantics. This slice does not compare their complete implementations or establish that one is atomic. Fixture cases must cover folder-versus-object confusion, an already-existing destination, a changed object between inspection and rename, settings references, redirectors, partial helper failure and a failed reload. Native tests compare registry, references, affected config/settings, disk paths and reload; no generic rollback is inferred.

## CAP-06: deletion remains held

The pinned UE [actor delete](https://github.com/db-lyon/ue-mcp/blob/62bb9a8f4a41b8ce5ff9a0fbbd5fbe0f49a39c7d/plugin/ue_mcp_bridge/Source/UE_MCP_Bridge/Private/Handlers/Level/LevelHandlers.cpp#L1268-L1353) refuses ambiguous labels, but calls `World->DestroyActor` without checking its return before reporting deleted. Its recorded inverse explicitly describes loss of properties, identity, references and potentially World Partition placement. The pinned EngineWire [actor delete](https://github.com/ChiR24/Unreal_mcp/blob/5a17d6d343ef9b40a509068cff73f1bfb4509815/plugins/EngineWire/Source/EngineWire/Private/Domains/ControlActor/McpActorLifecycle.cpp#L5-L101) checks actual destroy return and returns deleted/missing information including partial failure, but its lookup and automatic game-world behavior still need exact-world and identity qualification. These are different tradeoffs, not a safe universal deletion winner.

For assets, the pinned EngineWire [delete handler](https://github.com/ChiR24/Unreal_mcp/blob/5a17d6d343ef9b40a509068cff73f1bfb4509815/plugins/EngineWire/Source/EngineWire/Private/Domains/AssetWorkflow/Operations/McpAssetAssetMutation.cpp#L138-L310) checks registry/disk and reports deleted, missing, referenced and failed paths. It accepts folders and reports aggregate success if any path is deleted, so a successful outer envelope does not establish all requested paths were deleted. The [UE asset delete candidate](https://github.com/db-lyon/ue-mcp/blob/62bb9a8f4a41b8ce5ff9a0fbbd5fbe0f49a39c7d/plugin/ue_mcp_bridge/Source/UE_MCP_Bridge/Private/Handlers/Asset/AssetHandlers.cpp#L2942-L3020) has separate reference/PIE guards but the existing audit records a registry-orphan-file gap. Broad or force cleanup is not a substitute for exact reference-aware deletion.

Keep CAP-06 held until exact target, referencer, disk and persistence semantics are established. Negative fixtures must retain item A success when item B is missing/referenced/fails, recognize aggregate success with partial results, check stale references and loaded-package disk remnants, and fence an uncertain post-dispatch outcome. Native evidence must inspect memory, registry, references, files, save/reload and explicit user-authorized recovery; a lossy inverse is not rollback.
