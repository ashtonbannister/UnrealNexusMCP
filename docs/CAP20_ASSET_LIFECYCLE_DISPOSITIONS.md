# CAP-20 asset lifecycle: bounded source dispositions

Status: **source-review slices only** against the immutable provider pins in `catalog/upstreams.lock.json`. These are candidate/task assignments, not whole-record equivalence, callable Nexus routes, native qualification or a replacement for the authoritative machine-readable ledger. Compare schemas, loaded runtime, licenses and failure paths before selecting any provider. The ledger entries named below remain unreviewed until their full records and other selectors receive disposition. See [CAP-03–06 source review](CAP03_06_SOURCE_REVIEW.md).

## CAP-04: import

- **`ue-mcp / import_file`**: preserve as generic factory-import candidate, not as an already selected no-overwrite operation. The pinned [import implementation](https://github.com/db-lyon/ue-mcp/blob/62bb9a8f4a41b8ce5ff9a0fbbd5fbe0f49a39c7d/plugin/ue_mcp_bridge/Source/UE_MCP_Bridge/Private/Handlers/Asset/AssetHandlers_Import.cpp#L880-L1025) defaults `replaceExisting` to true, checks a path before import, and reports per-asset save results. A safe child contract needs authorized source ownership through actual dispatch, exact destination, explicit replacement policy, factory/class validation and honest partial save results. Source path existence is not a pinned source handle or proof that a factory respects no-overwrite.
- **`enginewire / asset.import`**: retain as a separate import candidate under CAP-04. Its [pinned import/duplicate implementation](https://github.com/ChiR24/Unreal_mcp/blob/5a17d6d343ef9b40a509068cff73f1bfb4509815/plugins/EngineWire/Source/EngineWire/Private/Domains/AssetWorkflow/Operations/McpAssetImportDuplicate.cpp#L188-L285) includes Interchange/task behavior and a collision helper. Inspect the complete target check and task replacement settings together; do not infer safe no-overwrite from a caller option or compare it as equivalent to a restricted pinned-handle import.

Fixture requirements: occupied destination, changing source after preflight, factory failure, multiple products and a partial save failure; preserve the exact output and never replay an uncertain import. Native acceptance additionally checks the actual source, registry, package bytes and reload.

## CAP-05: rename, move and duplicate

- **`ue-mcp / rename_asset`**, **`ue-mcp / move_asset`**: distinct exact lifecycle slices require source and destination identity. The [pinned rename handler](https://github.com/db-lyon/ue-mcp/blob/62bb9a8f4a41b8ce5ff9a0fbbd5fbe0f49a39c7d/plugin/ue_mcp_bridge/Source/UE_MCP_Bridge/Private/Handlers/Asset/AssetHandlers.cpp#L2542-L2708) can return an existing-destination no-op when the source is absent, and a world case can instead reconcile orphaned external packages. Destination existence does not prove that the destination is the originally requested object or that a prior attempt completed. World/external-package moves remain a distinct contract.
- **`enginewire / asset.rename`**: retain separately under CAP-05. The [pinned handler](https://github.com/ChiR24/Unreal_mcp/blob/5a17d6d343ef9b40a509068cff73f1bfb4509815/plugins/EngineWire/Source/EngineWire/Private/Domains/AssetWorkflow/Operations/McpAssetAssetMutation.cpp#L18-L127) can dispatch folder work and follow settings, with verification conditional on loading. An exact-object contract must exclude folder intent and explicitly cover any settings effects.
- **`ue-mcp / duplicate_asset`**, **`enginewire / asset.duplicate`**: preserve duplication as a distinct CAP-05 candidate, not equivalent to rename or guaranteed exclusive creation. Review the [UE duplicate handler](https://github.com/db-lyon/ue-mcp/blob/62bb9a8f4a41b8ce5ff9a0fbbd5fbe0f49a39c7d/plugin/ue_mcp_bridge/Source/UE_MCP_Bridge/Private/Handlers/Asset/AssetHandlers.cpp#L2081-L2164) and [EngineWire import/duplicate operations](https://github.com/ChiR24/Unreal_mcp/blob/5a17d6d343ef9b40a509068cff73f1bfb4509815/plugins/EngineWire/Source/EngineWire/Private/Domains/AssetWorkflow/Operations/McpAssetImportDuplicate.cpp#L188-L345) for existing destinations, recursive scope, returned identity and persistence. An existing destination is not evidence of which source produced it.

Fixture and native review must cover changed identities, source disappearance, existing destinations, folder confusion, world externals, failed saves, redirectors and reload. No inverse is represented as atomic rollback.

## CAP-06: deletion remains held

- **`ue-mcp / delete_asset`**, **`ue-mcp / delete_asset_batch`**: exact deletion and partial batch deletion are distinct held slices. The [single-delete source](https://github.com/db-lyon/ue-mcp/blob/62bb9a8f4a41b8ce5ff9a0fbbd5fbe0f49a39c7d/plugin/ue_mcp_bridge/Source/UE_MCP_Bridge/Private/Handlers/Asset/AssetHandlers.cpp#L2942-L3020) has an absent-registry path that does not itself prove orphan files absent. The [batch handler](https://github.com/db-lyon/ue-mcp/blob/62bb9a8f4a41b8ce5ff9a0fbbd5fbe0f49a39c7d/plugin/ue_mcp_bridge/Source/UE_MCP_Bridge/Private/Handlers/Asset/AssetHandlers.cpp#L3023-L3118) processes rows independently and skips invalid or empty elements; aggregate receipt and per-item failure/refusal must not be collapsed.
- **`enginewire / asset.delete`**: retain as a separately reviewed held candidate. Its [pinned asset mutation handler](https://github.com/ChiR24/Unreal_mcp/blob/5a17d6d343ef9b40a509068cff73f1bfb4509815/plugins/EngineWire/Source/EngineWire/Private/Domains/AssetWorkflow/Operations/McpAssetAssetMutation.cpp#L138-L310) includes folder and partial deletion behavior; a success envelope is not evidence every requested object is gone.

Deletion requires explicit authority over exact targets, referencer and disk checks, per-item outcomes, partial-failure handling, and separately observed native state and reload. CAP-06 remains held; these source records are not permission to perform deletion.
