# PIE ownership contract: proposed native design

This is the historical proposed contract. The v4 candidate implements request-correlated native ownership; see [owned PIE qualification](qualification/UAP_OWNED_PIE_20261112.md) for its actual scope and remaining limits. It is not an authenticated principal or a universal cross-client lock.

At pinned UAP revision `4ab7a62eb78612c2ec110f683b6e11f5dea62e95`, [`RequestPlaySession`](https://github.com/ImagineTheGames/UnrealAgentPlayer/blob/4ab7a62eb78612c2ec110f683b6e11f5dea62e95/Plugin/Source/UnrealAgentPlayer/Private/UAPAgentSubsystem.cpp#L198-L224) queues a global request; [`UAPRequestStopPIE`](https://github.com/ImagineTheGames/UnrealAgentPlayer/blob/4ab7a62eb78612c2ec110f683b6e11f5dea62e95/Plugin/Source/UnrealAgentPlayer/Private/UAPAgentSubsystem.cpp#L297-L332) cancels any queued request and may stop the current world. PIE delegates report state changes but no request or owner correlation. The pinned [machine lock](https://github.com/ImagineTheGames/UnrealAgentPlayer/blob/4ab7a62eb78612c2ec110f683b6e11f5dea62e95/mcp-server/src/unreal_agent_player/coordination.py#L1806-L1835) allows same-project pass-through; [project-wide release](https://github.com/ImagineTheGames/UnrealAgentPlayer/blob/4ab7a62eb78612c2ec110f683b6e11f5dea62e95/mcp-server/src/unreal_agent_player/coordination.py#L1939-L1971) is not an exact owner-bound release. Strict status v2 removes a false-idle fallback but does not solve those boundaries.

The proposed native boundary must atomically establish an editor epoch, an opaque owned request identifier and an exact grant before creating a queued start; refuse an already-active or foreign request; and bind the later play world/session to that request. Stop must validate that ownership, epoch and request/session identity at the native mutation point. A gateway-local map, an arbitrary model-supplied ID, or a machine grant alone does not establish it. Atomic idle and identity checks must be supplied and verified by a future native protocol. Matching request/session strings require a future trusted native mechanism to correlate the callbacks; caller-supplied equality does not establish event attribution. `confirmed` teardown and grant release likewise stand for trusted native observations, not caller assertions. Unconfirmed identity must leave the operation outcome uncertain; it cannot be retried merely by asserting a later positive witness.

A future implementation must test these rules: wrong owner or identity refuses, queued start can be canceled only by its owner, crossed or externally changed state fences, restart invalidates ownership, and a grant is released only after correlated confirmed teardown and confirmed owner-bound release. Timeouts and failed cleanup remain unresolved. A standalone model cannot observe direct clients, stop Unreal, establish a grant, authenticate anyone or prove engine event ordering.

Before implementing or releasing a native route, inspect the exact selected Unreal engine APIs for queue replacement and delegate correlation, establish a host-controlled capability boundary and unique native epoch/session proof, prove atomic owner checks at the game-thread transition, and verify ownership-aware release. Explicitly test manual/direct-client interference, stale or crossed callbacks, same-project competing agents, queued cancellation, teardown/restart and late replies. Record actual loaded artifacts and live results under LIVE-03; reconcile pre-existing PIE and machine grants externally. Do not use a blind retry, project-wide release, gateway reset or provider fallback as recovery.
