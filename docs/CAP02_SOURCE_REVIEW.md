# CAP-02 source review: sessions and ownership

Status: **source review and contract proposal only**. No new Nexus route, native patch, ownership guarantee, editor execution or qualification is established. CAP-02 depends on CAP-01; the [capability backlog](CAPABILITY_BACKLOG.md#cap-02), [coordination audit](audit/coordination.md) and pinned catalog remain authoritative. The proposed constraints below are admission criteria, not claims about the present adapters.

## Candidate owned-session contract (not selected)

1. **Open:** the host chooses an enabled, fixed native capability, one exact project/editor epoch and an exact resolved Blueprint identity. The request names the intended graph, bounded timeout and memory-only scope. Native code must atomically report a newly created session versus pre-existing/reused or refused session, and bind a Nexus-controlled owner token to that session and asset at acquisition. A preflight list plus ordinary `bp_open` cannot prove creation or prevent another caller from opening or retargeting between calls. Refuse pre-existing sessions rather than adopting them silently. If the selected native build cannot provide atomic owner binding and unambiguous creation, hold the route or require an explicitly reviewed compatible native change.
2. **Read:** a bounded, fixed status route checks the same editor epoch, owned token, asset and native handle and reports live/expired/closed/unknown, cursor/graph identity and dirty or persistence state only when the native source actually exposes each. Do not infer session liveness from a cached id, elapsed time, a process-local queue or file existence. Distinguish unknown from closed. Never present cooperative labels as authenticated principals.
3. **Use:** a compile-session request is allowed only for a handle created and still owned in the current host/editor epoch, with exact provider/source and the required no-autosave compatibility marker verified under current gateway rules. Preserve native compile diagnostics and any returned session/asset identity; no auto-replay, provider failover or inference that a missing receipt means no effect. Any future foreign-session workflow must be a separately authorized contract and not manufacture ownership.
4. **Close:** offer only an explicit exact owned handle and explicit persistence mode. Memory-only close needs a source-proven/native-verified no-save contract and actual dirty-state behavior; persist requires separate write authority, exact asset scope, a checked save receipt and subsequent readback/reload. Neither `session_release(force_all)` nor asset-path force-release is an acceptable substitute. A native close refusal/unknown or lost connection retains an unresolved owned resource and must not be relabeled released or retried automatically. Runtime shutdown does not silently close sessions, save, discard or release native state.
5. **Epoch/restart:** bind the handle to project identity, provider, host process epoch and attested editor start identity; before each transition reject an epoch mismatch. Invalidate local eligibility on reconnect or restart without claiming the native session has gone away. Observe and reconcile late operations and any external resources before a deliberate restart.

A process-local owner registry alone can enforce its own callers' use but cannot prevent same-tool native reuse by direct clients or another gateway. Strong cross-client ownership therefore needs an explicitly reviewed native identity/lease contract or a narrower honestly documented guarantee, not a relabeling of current manager behavior. Source evidence and compatibility patch hashes do not prove a loaded native module.

## Required fixture and native evidence

- Exercise new versus reused/foreign handles, two HTTP clients and a separate direct client; race simultaneous opens, same-tool graph retarget, close and expiry. A successful case must show who actually created the native session and whether another caller can observe, use, close or redirect it.
- Reject malformed, unknown, foreign and stale handles before requested work; test editor/process epoch change, provider reconnect, timeout and late open/close response. Preserve original receipt and fence any uncertain post-dispatch work; no reset, auto-resend or automatic provider switch.
- Compare no-autosave wrapper with the reviewed patch and live marker, compile an existing exact session, retain compiler diagnostic outcomes, and record native package dirty state. Test disk hashes/reload for explicit memory-only close, explicit save, close-all and generic force-release separately. A native `SkipSave` flag or source description is insufficient persistence evidence.
- Inject rejected close, transport loss, cleanup timeout and expiry; distinguish failed, closed, expired and unknown; retain unresolved ownership through shutdown. Test that a missing close acknowledgement never triggers force-release of another session. Check lease orphan/renew/expiry and machine hold release independently; these do not establish authenticated cross-client exclusion.
- Retain exact Nexus commit/lock, provider pin and compatibility patch hash, loaded binary/marker, engine/project/editor epoch, exact arguments, original MCP receipt, pre/post state, artifact hashes and operator-owned cleanup record. Only a named disposable-project run can establish native qualification; source and fixture tests do not.
