# UAP strict PIE status v2: source/fixture proposal

Status: **proposal only; not registered, built, deployed, or live-qualified**. This is a separate combined source delta based on the unchanged UAP pin `4ab7a62eb78612c2ec110f683b6e11f5dea62e95`; it includes the already-reviewed v1 no-replay/binding behavior and adds strict status handling. It does not supersede the active `uap-nexus-no-replay-v1` manifest, change any executable route or lift the current PIE holds.

## Evidence and change

The pinned [PIE tool](https://github.com/ImagineTheGames/UnrealAgentPlayer/blob/4ab7a62eb78612c2ec110f683b6e11f5dea62e95/mcp-server/src/unreal_agent_player/tools/pie.py#L12-L24) defaults a missing phase to `NotPlaying` and missing elapsed time to `0.0`. The [Remote Control client](https://github.com/ImagineTheGames/UnrealAgentPlayer/blob/4ab7a62eb78612c2ec110f683b6e11f5dea62e95/mcp-server/src/unreal_agent_player/transport.py#L129-L167) returns an empty object when response JSON cannot be decoded. The exact pinned [native enum](https://github.com/ImagineTheGames/UnrealAgentPlayer/blob/4ab7a62eb78612c2ec110f683b6e11f5dea62e95/Plugin/Source/UnrealAgentPlayerRuntime/Public/UAPAgentTypes.h#L8-L15) is `NotPlaying`, `Starting`, `Playing`, `Paused`, and `Ending`. In particular, `Ending` is not a confirmed stop.

[`uap-nexus-strict-status-v2.patch`](../patches/uap-nexus-strict-status-v2.patch) is a combined v1-plus-status delta. In the Nexus-only bound-client mode it accepts only those exact phase strings and a finite, nonnegative numeric elapsed value, and otherwise raises nonrecoverable `UE_STATUS_UNVERIFIED`. Stock mode retains the pinned fallback behavior. The existing Nexus no-replay behavior retains its machine grant after ambiguous Python dispatch; malformed status after a dispatched start/stop propagates without a stop/replay or project-grant release. The proposed `bridge_status` marker describes the configured validation behavior; its presence is not independent proof of editor identity or loaded binaries.

The proposal manifest [`uap-strict-status-v2-proposal.json`](../catalog/uap-strict-status-v2-proposal.json) records the complete patch digest, exact source-before/source-after digests, base revision and marker. It is **not** an entry in `compatibility-patches.json` and cannot select or authorize this proposal.

## Fixture scope and integration gate

`test/uap-strict-status-v2.test.mjs` checks the patch digest, applies each hunk in memory against the exact pinned source bytes, verifies resulting hashes, and compiles only explicitly named functions in an isolated Python namespace. Fake RC/transport/machine clients exercise valid native phase names, malformed/missing phase and elapsed values, Nexus-only mode binding, the marker, stock fallback, and retained grants after invalid phase following one dispatched start/stop. The pristine source checkout is never imported or modified; no Unreal engine, native plugin, real listener, machine grant or live editor is exercised. Set `NEXUS_UAP_SOURCE_ROOT` to a pristine exact checkout for this fixture.

Before any promotion, independently review the complete patch and its six source hashes; add an explicit active v2 compatibility manifest and any necessary pin/pack/config migration; update host probes to require the exact v2 marker and reject absent or mismatched evidence; add source-verification and runtime regression coverage; and validate native Remote Control enum serialization and elapsed types against the actual selected engine and loaded artifacts. Unknown or differently serialized enum values intentionally fail closed. `bridge_status` may report phase `null` when validation fails; a v2 consumer must not treat marker presence or RC reachability alone as a successful phase read.

**Ownership remains a separate hard gate.** Strict phase validation does not prove that the current PIE session, queued start or machine grant belongs to a Nexus workflow; it does not prevent independent clients from replacing them. The `pie.start.viewport`, `pie.stop`, and `pie.status` holds must not be lifted merely because these source fixtures pass. Start/stop additionally need a reviewed native atomic owner/epoch-bound protocol, while status needs the live strict-phase evidence above. Externally reconcile any existing PIE session or machine grant; no implicit stop, reset or cleanup is added.
