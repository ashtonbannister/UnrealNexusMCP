# Owned PIE lifecycle - 2026-11-12

The v4 UAP compatibility patch supplies owned in-process viewport PIE start and stop. Nexus retains an opaque backend-only owner token, the native editor epoch and session ID, and a unique machine grant. The native plugin correlates Unreal's duplicated play-settings object across the queued request and active session. It refuses a foreign replacement, mismatched token or unconfirmed transition. Stop validates the same owner before cancellation or teardown; the server releases only its unique grant after native end and owner release are confirmed.

The provider refuses same-project machine-lock pass-through for this route and checks its exact grant before start and stop. The grant uses a long-lived expiry instead of the upstream ten-minute default: an uncertain or crashed owner must be reconciled by an operator, rather than silently expiring. Other direct clients and force-release operations do not automatically honor Nexus ownership; this is not an authenticated principal or a universal cross-client lock. Do not retry an uncertain dispatch or infer rollback.

Unreal 5.8's in-process viewport request can still trigger saves if the configured multiplayer settings require another process. The patch checks those settings and refuses that combination before requesting PIE. This guard does not claim that arbitrary editor extensions or user code cannot save.

The combined patch is based on UAP `4ab7a62eb78612c2ec110f683b6e11f5dea62e95`, includes the v3 queued-status and single-dispatch fixes, and has SHA-256 `cc11432be648d643fe68a4e9b22ec94004c1ce1956e13bacdcc0951f4ab2502c`. It is `patches/uap-nexus-owned-pie-v4.patch`. The coordinator requires the exact source patch, status/no-replay/ownership markers, reflected native methods and their parameter signatures. A configured UAP probe deadline is bounded by the host timeout and capped at 30 seconds.
