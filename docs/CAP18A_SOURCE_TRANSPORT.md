# CAP-18A pinned transport and dispatch evidence

Status: **source review only**. The owner selected direct bounded image bytes on 2026-10-28; this is not an implementation, native build, or live qualification. The [image-delivery design](CAP18A_IMAGE_CONTRACT.md) and [fixture PNG checks](CAP18A_PNG_FIXTURE.md) remain proposals; the [backlog](CAPABILITY_BACKLOG.md#cap-18a) is the task authority. No provider or route has been changed.

## Capture, selection, and file side effect

At UE-MCP `62bb9a8f4a41b8ce5ff9a0fbbd5fbe0f49a39c7d`, the [native capture handler](https://github.com/db-lyon/ue-mcp/blob/62bb9a8f4a41b8ce5ff9a0fbbd5fbe0f49a39c7d/plugin/ue_mcp_bridge/Source/UE_MCP_Bridge/Private/Handlers/Editor/EditorHandlers.cpp#L2822-L2963) scans PIE world contexts against the provided instance and optional world selector. Its world selector accepts either `GetPathName()` or `GetName()`, and it picks the first matching context with a capturable viewport; the reviewed loop does not establish rejection if multiple contexts match. The currently exposed canonical schema narrows `worldPath` to slash-prefixed strings, but that is not proof of uniqueness or a native atomic target lock. A future contract promising exact identity needs a native uniqueness check and the actual resolved context in its correlated receipt.

The handler captures the selected Slate widget, allocates a pixel array, encodes PNG, checks whether the destination exists, and then uses a separate path-based write. It reports `overwrote` only after the write. A unique-looking user-supplied filename and a preflight `FileExists` observation cannot establish exclusive creation under concurrent writers. This is a source-established possible overwrite, not an observed live overwrite. The existing screenshot operation and the proposed delivery operation must preserve explicit overwrite authority and must not claim no-clobber without an independently reviewed native mechanism.

## Bridge and MCP response path

- The native [WebSocket limits](https://github.com/db-lyon/ue-mcp/blob/62bb9a8f4a41b8ce5ff9a0fbbd5fbe0f49a39c7d/plugin/ue_mcp_bridge/Source/UE_MCP_Bridge/Private/BridgeWebSocket.h#L38-L60) bound accumulated **incoming** native messages to 64 MiB. This is not evidence of an end-to-end outgoing image size limit.
- The pinned Node bridge [creates the WebSocket](https://github.com/db-lyon/ue-mcp/blob/62bb9a8f4a41b8ce5ff9a0fbbd5fbe0f49a39c7d/src/bridge/bridge.ts#L688-L700) without an explicit `maxPayload` option at this call site. No limit or absence of a library default is inferred from that omission; the exact dependency version and defaults need separate inspection.
- Its [listener](https://github.com/db-lyon/ue-mcp/blob/62bb9a8f4a41b8ce5ff9a0fbbd5fbe0f49a39c7d/src/bridge/bridge.ts#L1017-L1062) converts the incoming WebSocket payload to text and parses the full JSON before matching an ID to a pending request. It retains late responses for abandoned calls. Thus an application-level post-parse PNG length check alone cannot bound the earlier response allocation, and a late response does not authorize retry.
- The [category dispatcher](https://github.com/db-lyon/ue-mcp/blob/62bb9a8f4a41b8ce5ff9a0fbbd5fbe0f49a39c7d/src/dispatch/server-dispatch.ts#L386-L420) serializes the result into MCP text content. Native JSON carrying encoded bytes would remain text unless an explicitly reviewed adapter converts a validated result into an MCP image. The conversion must retain the original receipt, warnings and any error, and respect the entire transport envelope; the `screenshot.pie` filename response is not an image block.

## Independent implementation gates

The selected direct-byte direction needs a separately selected fixed method and schema, native capture and encoding bounds applied before allocation, strict identity/epoch correlation, response framing limits across native WebSocket, Node `ws`, JSON and MCP, and a tested bound on both encoded and decoded data. Raw PNG base64 needs `4 * ceil(bytes / 3)` characters before JSON/MCP framing; extra fields and escaping also consume space. The actual budget must be measured and enforced at every allocating boundary, not inferred solely from the inbound native limit. A malformed, crossed or timed-out post-dispatch response remains uncertain and fences the shared editor queue.

A file-lease alternative instead requires the reviewed Windows handle/ACL, private release, bounded lifecycle and unresolved cleanup protocol in the [proposed design](CAP18A_IMAGE_CONTRACT.md). File identity, SHA and size can correlate simultaneous verified handles; a pathname, digest alone, or a past realpath observation cannot establish ownership. The unselected file-lease protocol must not be used as an automatic fallback for direct bytes.

The existing fixture PNG validators prove only the narrowly stated local checks; they neither implement the selected transport nor bind bytes to a live editor. No extra mock frame parser is added here: without a selected wire contract it would not verify an actual boundary. Before route exposure, record the chosen protocol, patch and marker, exact source/build evidence, bounded response and negative-case fixtures, and per-profile native capture, lifecycle and cleanup results.
