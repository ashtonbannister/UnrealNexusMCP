## Scoped before/after: generation wait and run identity

The locked [`pcg-wait.ts`](https://github.com/db-lyon/ue-mcp/blob/62bb9a8f4a41b8ce5ff9a0fbbd5fbe0f49a39c7d/src/tools/pcg-wait.ts) treats a matching `not_started` run as terminal when the component is not busy. The [candidate wait implementation](https://github.com/db-lyon/ue-mcp/blob/7ef5b2c285ed3251dd2b5ac0569b8749683fd381/src/tools/pcg-wait.ts#L66-L130) delays that terminal result for a configurable grace window (default two seconds), and adds `alreadyGenerated`, `lastFinishUtc`, `lastFinishState` and `note` to `not_started` results. This changes timing and extends the receipt; it does not establish that a generation actually started. Both versions retain `not_started` as a possible state, and Nexus's current exact-run wait still requires `generated` and matching run identities.

The [candidate native run record](https://github.com/db-lyon/ue-mcp/blob/7ef5b2c285ed3251dd2b5ac0569b8749683fd381/plugin/ue_mcp_bridge/Source/UE_MCP_Bridge/Private/Handlers/PCG/PCGHandlers.cpp#L553-L603) associates a generation observed within 30 seconds after `not_started` with the prior run, marking `deferredStart`. The reviewed code checks the component and elapsed window; it does not establish causation from an independent direct client. **Inference requiring validation:** another client's later generation within that window might be attributed to the prior run. Nexus's process-local queue cannot prevent a direct-client action. Preserve the `not_started` distinction and require concurrency and timeout tests before treating this candidate as an equivalent or safer replacement.

The [candidate public PCG declarations](https://github.com/db-lyon/ue-mcp/blob/7ef5b2c285ed3251dd2b5ac0569b8749683fd381/src/tools/pcg.ts#L10-L35) also describe ordinary node pin lists for `read_graph`; the locked handler read previously reviewed does not expose ordinary-node pins. Candidate generated PCG specs add component-parameter operations and other schema changes. Those are separate discovery/authoring candidates under CAP-01/CAP-17, not an automatic change to `pcg.graph.connect.persisted` or the executable allowlist. Stable graph revisions, bounded reads and atomic stale-identity checks remain to be established.

## Decision and gates

- **Retain:** existing pinned UE provider and its 12 selected canonical routes. No automatic failover, retry, route widening, or upgrade is authorized by this comparison.
- **Review candidate:** deferred run correlation and grace behavior as a distinct change; test deferred start, already-generated no-op, explicit run identity, a competing direct-client generation inside and outside the window, replacement by a later run, timeout and restart. Compare exact schemas, fixed selectors, capability probes and original/partial receipts.
- **Keep distinct:** read-only graph/pin discovery versus persisted connection mutation; current run identity versus observed component output; a no-op `not_started` result versus generated output. Added PCG component operations require their own provider comparison and target/save contracts.
- **Not assessed:** remaining changed routes, all 94 commits individually, new transitive dependencies and nested third-party licenses, native binaries and behavior, and any changed networking/security boundaries. The root `LICENSE` file is unchanged across these revisions, but that is not a complete component-license review. The root's existing notice remains applicable; inspect every newly introduced component before reuse.

No new live result is asserted here.

If a future promoted run becomes uncertain, reconcile outstanding native work first; operator-directed rollback must update lock, decision, adapter/schema, guidance, compatibility evidence and qualification together. Never automatically replay the mutation or switch providers as rollback.
