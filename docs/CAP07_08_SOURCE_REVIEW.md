# CAP-07 and CAP-08: Blueprint source review

Status: **source review only** against Nexus baseline `985426c`; no new canonical route, provider selection, native build or editor qualification. CAP-07 and CAP-08 remain blocked on CAP-01 discovery; session variants additionally need CAP-02. The existing memory-only Blueprint compile routes are separate contracts and remain governed by their existing decision and compatibility requirements.

## CAP-07: creation and structural authoring

The pinned UE-MCP [Blueprint wrapper](https://github.com/db-lyon/ue-mcp/blob/62bb9a8f4a41b8ce5ff9a0fbbd5fbe0f49a39c7d/src/tools/blueprint.ts#L19-L30) describes creation by destination and node-level graph actions. Its [native create handler](https://github.com/db-lyon/ue-mcp/blob/62bb9a8f4a41b8ce5ff9a0fbbd5fbe0f49a39c7d/plugin/ue_mcp_bridge/Source/UE_MCP_Bridge/Private/Handlers/Blueprint/BlueprintHandlers.cpp#L1730-L1828) normalizes the asset path, resolves the parent class by short name or path, and checks for an existing Blueprint. An existing Blueprint is returned by default, including its actual parent, while `onConflict=error` refuses it. New creation calls AssetTools and compilation, then returns object and parent paths; the reviewed creation body does not call its checked save helper or report a save result. The rollback descriptor names deletion, but is not evidence that deletion is safe or automatic rollback occurred. Compilation invocation alone is not a compiler-diagnostics or successful-persistence contract.

At EngineWire `5a17d6d343ef9b40a509068cff73f1bfb4509815`, [the create wrapper](https://github.com/ChiR24/Unreal_mcp/blob/5a17d6d343ef9b40a509068cff73f1bfb4509815/plugins/EngineWire/Source/EngineWire/Private/Domains/BlueprintCreation/McpBPCreateHandlers.cpp) parses a name, sanitized save path and parent/type selectors. [Its creation body](https://github.com/ChiR24/Unreal_mcp/blob/5a17d6d343ef9b40a509068cff73f1bfb4509815/plugins/EngineWire/Source/EngineWire/Private/Domains/BlueprintCreation/McpBPCreateAssets.cpp) compares the requested parent when one resolves, attempts to save a created asset before returning, reports `saved`, and retains applied/failed property lists when applicable. A property failure does not undo creation. Existing-asset behavior differs from UE-MCP; a response or `saved` flag still needs native readback and reload evidence. Unknown class resolution, non-Blueprint path collisions, concurrent creates and source-controlled/read-only packages need specific review.

### Candidate child contracts

1. **Exact create without replacement.** Require an explicit canonical package/object destination, full parent class identity, Blueprint type, conflict policy and effect/persistence scope. Distinguish `created` from `already existed`, and never accept an existing asset of the wrong parent/type as satisfying a request. Capture any asset created before later compile/save errors. Do not equate source-reported save with independent disk/reload proof.
2. **Granular structural edits.** Create graphs, variables, nodes and components only through individually reviewed fixed selectors. Each child needs exact asset, graph and node identity; accepted types and parent constraints; whether compilation, save or reconstruction occurs; per-item partial effects and explicit readback. Do not collapse these into a generic raw backend route or claim a batch atomic.

A source-backed native adapter/patch may be needed to enforce exact class/destination and conflict semantics at the mutation boundary. The source review does not pick one. Fixture cases should cover a pre-existing same/wrong-parent asset, invalid or ambiguous class, wrong-type collision, invalid destination, failure after creation, property partial failure, compile error, save refusal and post-dispatch loss. Native cases must observe registry/object identity, dirty state, diagnostic results and explicit save/reload, with unrelated assets unchanged. An independent cleanup strategy must account for created assets without automatically deleting them.

## CAP-08: graph connections

The pinned [UE-MCP connect handler](https://github.com/db-lyon/ue-mcp/blob/62bb9a8f4a41b8ce5ff9a0fbbd5fbe0f49a39c7d/plugin/ue_mcp_bridge/Source/UE_MCP_Bridge/Private/Handlers/Blueprint/BlueprintHandlers_Graph.cpp#L1011-L1335) accepts a graph selector, two node identifiers, pin names and break flags. It selects the first name-matching pin on each node, uses the graph's actual schema, records previously broken link details, compiles unless deferred and invokes checked save. A pre-existing link with nothing else to break returns early as an existing result; break flags can still change other links even if the target link already exists. On failed connection the implementation attempts to restore links and the original clean dirty flag. These code paths are not proof of restoration of every schema side effect, reconstruction, conversion or persisted state.

The pinned [Claireon session connection](https://github.com/believer-oss/Claireon/blob/89bee2f4c62d1df625cca71ae66e7c81a415a009/Source/Claireon/Private/Tools/ClaireonBlueprintGraphTool_ConnectPins.cpp#L234-L417) supports GUID/title node resolution with title ambiguity refusal, resolves pins with direction hints and fuzzy-name warnings, uses `UEdGraphSchema_K2`, and propagates wildcard and node reconstruction effects. It marks the Blueprint modified; this is not the same as an independently saved arbitrary-schema connection. Existing session and public wrapper requirements apply.

The pinned [EngineWire connection](https://github.com/ChiR24/Unreal_mcp/blob/5a17d6d343ef9b40a509068cff73f1bfb4509815/plugins/EngineWire/Source/EngineWire/Private/Domains/BlueprintGraph/McpBPGraphPinMutations.cpp#L18-L199) can allocate or grow pins, reinterpret a variable-Set endpoint, invoke the actual graph schema, report a detected conversion node and link changes, and attempt a throttled save. These conveniences are observable semantic changes, not an exact no-conversion contract. In the reviewed excerpt save is invoked before response but its return value is not included in that call; independently check the complete adapter and readback before any persistence claim.

### Proposed separation and acceptance

- **Exact direct connection:** bind asset, exact graph identity and revision/epoch, full node and pin identities including direction and schema, expected existing links and a fixed break policy. Refuse ambiguous names, stale identities, unwanted pin growth, implicit endpoint reinterpretation or conversion unless the selected child contract expressly permits and reports them. A separate explicit conversion-aware variant can preserve useful provider behavior.
- **Session/memory variant:** require a valid owned session and no implicit save; record wildcard propagation and all reconstructed or affected nodes. Keep it distinct from the persisted variant.
- **Persisted variant:** report direct versus conversion-mediated topology, all replaced links, compile diagnostics and actual save result, followed by independent graph readback and reload when persistence is claimed. An already-connected no-op must not be represented as a new link or blindly replayed.

CAP-01 must supply adequate graph/node/pin discovery and stale-revision handling before integration. Fixtures should exercise same-name input/output pins, duplicate titles, stale/reconstructed pins, existing requested edge with and without break flags, schema disallow, conversion insertion, pin growth, compile/save failure and lost response. Test changed links and dirty state after failure; do not infer atomic rollback from transaction or the restoration attempt. Native cases additionally require real graph/schema variations, compilation, disk reload and retained before/after evidence.
